Binary Search Tree and Hash Table Comparison:
In this assignment, I implemented a Binary Search Tree (BST) and a Hash Table using Java. I compared their performance for insertion, searching, and deletion. I tested both data structures with 100, 1,000, and 10,000 elements and measured execution time using System.nanoTime().
A BST stores values in nodes. Smaller values are placed on the left, and larger values are placed on the right. Its performance depends on the shape of the tree. If the tree is balanced, operations usually take O(log n) time. However, if the tree becomes unbalanced, they can take O(n) time. A Hash Table uses a hash function to calculate where a value should be stored. It usually provides O(1) average time for insertion, searching, and deletion when values are distributed well. However, collisions can make its operations slower.
In my experiment, the Hash Table was faster for insertion and searching at all three dataset sizes. It was also faster for deletion with 100 and 1,000 elements. However, when testing 10,000 elements, BST deletion was faster. The Hash Table took 11,477,800 nanoseconds for deletion, while the BST took 6,731,300 nanoseconds.
The results show that a Hash Table performed better in most of my tests. However, execution times can depend on the implementation, input data, collisions, and Java runtime behavior. Since I measured each operation only once, more tests would be needed to obtain more reliable results.
In conclusion, both data structures have advantages and disadvantages. A Hash Table is useful when fast searching is important, while a BST can be useful when data needs to be maintained in sorted order. The best choice depends on the requirements of the application.
